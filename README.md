# Hutano Field Companion

Offline-first health-documentation prototype for Zimbabwean Village Health Workers, built solo by Linda Kisimisi for the World Bank Small AI for Development health hackathon.

## Problem and solution

Field workers need to capture encounter notes when connectivity is unreliable, then check the resulting documentation before sharing it. Hutano saves notes locally, suggests fields with explicit source text, requires human verification, and uploads immutable verified revisions when connectivity and authentication are available.

**Use synthetic demo information only.** Hutano does not diagnose, prescribe, assess urgency or make treatment decisions. Shona interface support and Shona extraction quality are separate: model sentence selection in Shona remains unvalidated.

## AI and review workflow

1. Capture a Shona, English or mixed note. Save the draft in IndexedDB before extraction.
2. Choose manual entry, labelled deterministic demo extraction, or experimental on-device extraction.
3. In hybrid extraction, deterministic rules handle explicit structured fields. A pinned Qwen3 0.6B ONNX model selects sentence numbers for concern, observations and follow-up.
4. Validate the model output and reconstruct exact whole sentences from the original note. Reject malformed or unsupported selections; preserve source text and negation.
5. Show suggestions as pending with their rule/model provenance. The worker edits or accepts fields and acknowledges missing documentation.
6. Explicit verification creates an immutable revision and outbox item in one local transaction. Editing afterwards invalidates verification.
7. Upload the current account's verified revisions to external Supabase using insert/select-only access. A record becomes synced only for the acknowledged revision.

Inference runs in a dedicated Web Worker after an explicit model installation. The default is the compatibility CPU/WASM path; WebGPU is experimental. Download and inference are distinct steps. A successful download on a phone does not establish successful offline inference on that phone.

## Architecture and stack

| Component | Implementation |
| --- | --- |
| Application | React 19, TypeScript, TanStack Start and Router, Vite and Nitro |
| Local persistence | Dexie and browser IndexedDB |
| Model runtime | Pinned `@huggingface/transformers`, ONNX Runtime Web, Qwen3-0.6B-ONNX |
| Offline app shell | Workbox worker generated by a custom build plugin |
| Identity and upload | Browser Supabase client, email/password Auth, external PostgreSQL under RLS |
| Verification | Repository mutation boundary, revision and account guards, append-only local audit metadata |
| Tests | Vitest, Testing Library, fake-indexeddb; extraction, storage, audit, account and sync tests |

There are no cloud-AI calls or Supabase Edge Functions in this implementation. The app's first online load installs its offline shell. Model files use a separate cache and are downloaded only on request.

## Security decisions and limitations

- Every suggested value retains literal source evidence for human review.
- Local records are partitioned by owner ID. Signed-out records require explicit adoption before upload.
- Outbox draining is single-flight and account-epoch guarded. Lost acknowledgements are retried with the same revision ID; duplicates are accepted only when the server snapshot matches.
- The backend schema permits authenticated insert/select of owned, verified synthetic snapshots and forbids update/delete.
- Encounter data is not stored in localStorage or the service-worker app cache. Authentication sessions use the Supabase browser storage convention.
- IndexedDB encounter records are unencrypted. Sign-out hides records but does not erase them; no remote wipe is implemented.
- Upload requires the app to remain open. Background sync, downloading server records and two-way conflict resolution are not implemented.
- Evaluation artifacts use a small synthetic dataset. They do not establish clinical accuracy, field deployment performance or validated Shona model ability.

See [security review](docs/security-review.md) and [evaluation details](docs/evaluation/README.md).

## Local setup

```bash
bun install
cp .env.example .env.local
bun run dev
bun run test
bun run build
```

The example contains public configuration for the external demo backend; `src/lib/supabase.ts` has equivalent fallbacks. Use a separate project for independent development. Never add service-role credentials to browser configuration.

The external schema copy in `docs/backend/0001_encounter_revisions.sql` is documented as already applied. Do not re-run it against the existing backend. Read [backend instructions](docs/backend/README.md) before configuring a new environment.

Offline inference additionally requires an explicit model install, adequate browser storage and a supported runtime. The model/runtime download is roughly 600–650 MB depending on the chosen variant. Source tests and checked-in evaluation results are inspectable; they were not rerun as part of this documentation-only review.
