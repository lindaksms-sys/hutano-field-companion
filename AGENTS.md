## Hutano architecture rules
- All encounter persistence goes through `src/domain/repository.ts` mutate(); it bumps localRevision and invalidates verification — keeps audit/verification guarantees in one place.
- Extraction is behind the `ExtractionAdapter` interface; adapters must return exact narrative substrings as sources and never infer/translate — prevents hallucinated clinical data.
- Sync drains the IndexedDB outbox through the `RevisionStore` interface (insert/select only, single-flight, epoch-guarded); records become `synced` only for the exact acknowledged revision — no simulated sync, no overwrites.
- Backend is an external Supabase project used directly from the browser under RLS; do not enable Lovable Cloud. Schema copies live in docs/backend (already applied, never re-run).
- Local records are partitioned by `ownerId`; unowned records need explicit adopt — never transfer between accounts.
- Dexie DB is created lazily via getDB() — SSR must never touch IndexedDB.
- Service worker is generated by scripts/service-worker-plugin.ts into the client environment's outDir (not vite-plugin-pwa, which emitted to the wrong dir under Nitro) and registered only from `src/lib/pwa.ts` (guarded) — avoids 404s in deploys and stale caches in preview.
- Encounter data never goes to localStorage or telemetry.

- Extraction is hybrid: deterministic rules (`src/domain/rules.ts`, labelled rule/not AI) own structured fields and the model only selects sentences for narrative fields — keeps structured values explicit and provenance honest.
- Accuracy claims come only from `scripts/eval-extraction.ts` on the frozen held-out set (`eval/HELDOUT.sha256`); never tune on held-out cases.
- On-device AI runs only in `src/workers/ai-extraction.worker.ts` with the pinned model/revision in `src/lib/ai-config.ts`; the model only selects sentence numbers and `validateModelOutput` rebuilds exact whole-sentence sources — never trust model-written values.
- Model files live in their own Cache API cache (`hutano-ai-v1`), installed only by explicit user action and never in the app-shell precache — keeps the app small and removal safe for records.
- On-device AI install mode is an explicit user choice (default Compatibility/CPU); GPU is never auto-selected and the install never downloads a second variant automatically — only the tested path runs by default.
- Translator inventory `docs/shona-translation.csv` is generated by `scripts/shona-inventory.py` from source; regenerate rather than hand-edit keys — keeps keys stable and the inventory complete. Reviewer text lives only in `docs/shona-review-overlay.csv` (keyed by stable ID, merged on regeneration) and UI Shona comes only from the generated `src/lib/sn-strings.gen.ts` (`scripts/shona-ui-strings.py`, exact English text as key) via `tl`/`tf` in `src/lib/i18n.tsx`; only overlay rows with `ui_publish=yes` are published, so review-only alternatives never reach the UI automatically — reviewer work can't be lost and provisional terms stay out of the UI.
